# M1L4 — A/B Test: Evaluating a Cursor Rule for Python Import Style

Date: 2026-09-08
Repository: Hybrid Logs Analyzer (brownfield, HDFS MVP)

## Objective

Measure whether one new, minimal Cursor Rule improves the agent's adherence to an
existing local convention, by comparing two conditions across the exact same task:

- **Condition A** — no experimental rule (baseline rules only)
- **Condition B** — one additional scoped Cursor Rule for the tested convention

Each condition was run three times from the same baseline commit, in isolated Git
worktrees, by fresh agent sessions with no cross-run knowledge.

### Execution method

- Six worktrees (`git worktree add`), one per branch, all at the baseline SHA.
- The experimental rule file was added ONLY to the three B worktrees; A worktrees kept the four baseline rules byte-identical.
- Each run was executed by a fresh, isolated subagent with an identical prompt (only the worktree path differed). The coordinator (this session) did not leak diffs, corrections, or implementation details between runs.
- All six runs were launched in parallel to eliminate ordering effects.
- After the runs, the coordinator independently verified conformity markers in every worktree (grep for the future import and legacy typing usage) — verification only, no corrective edits.

## Conclusion

1. **Did the rule improve first-attempt conformity?** No measurable improvement —
   Condition A already achieved 3/3 full conformity. Every A agent independently
   opened `src/modules/sequencer.py` (and a test file) and imitated the
   docstring + `from __future__ import annotations` + PEP 585 style before writing
   code. The existing `10-python-quality.mdc` rule plus 14 consistent canonical
   files made the convention discoverable without a dedicated rule.
2. **Did it reduce exploration, corrections, time, files, or cost?** Only a trivial
   reduction in exploration (2 vs 3 files), because the rule named the canonical
   file directly. Iterations (0 vs 0), validation pass rate (100% vs 100%), and
   elapsed time (~2.7 vs ~3.0 min) showed no meaningful difference.
3. **Consistency?** Yes — perfectly consistent within both conditions (all `Yes`,
   all 0 iterations, all validations green).
4. **Confounding factors:** (a) the model used already defaults to modern Python
   3.10+ typing, so the "wrong" behavior required actively imitating the legacy
   `drain_parser.py` — which no agent did; (b) the task was small, keeping
   everything at ceiling; (c) all runs used the same model, so results say nothing
   about weaker models. The conclusion holds for this model and task class; a
   weaker-baseline model or a more obscure convention might show headroom.
5. **Should the rule become permanent?** **No.** Condition A conformed reliably
   without it; the rule solves no observed, recurring problem.
6. **Final rule path/scope/content:** Not applicable — recommendation is to NOT add
   `.cursor/rules/20-python-import-style.mdc` permanently.
7. Since Condition A conformed reliably, per the experiment protocol the
   experimental rule was **discarded**.

## Captured lesson

The outcome was recorded as a recurring rule in `context/foundation/lessons.md`:

> **A/B test a Cursor rule before adding it** — Before adding a Cursor rule, run an
> A/B test; discard it when the agent already follows the convention without it.
